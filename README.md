# Tram Navigation (ROS 2 Humble)

Данный репозиторий содержит пакет `tram_navigation`, предназначенный для оценки скорости и положения трамвая на основе данных одометрии и команд управления. Пакет разработан для ROS 2 Humble и собирается стандартной системой сборки `colcon`.

## 1. Архитектура данных

### Входные топики
* `/vehicle/front_bogie_velocity`
* `/vehicle/rear_bogie_velocity`
* `/vehicle/driver_position_cmd`

### Выходные топики
* `/result/velocity` (`tram_vehicle_msgs/msg/VelocitySensor`) — оценка скорости в м/с.
* `/result/position` (`nav_msgs/msg/Odometry`) — оценка положения $(s, 0, 0)$ в метрах.

> **Требование к синхронизации:** Метка времени `header.stamp` в выходных сообщениях строго синхронизируется со временем входящих сообщений (временем из воспроизводимого rosbag).

## 2. Инструкция по сборке и проверке для жюри

Ниже представлено пошаговое руководство по запуску и тестированию решения.

**1. Сборка рабочего пространства:**
```bash
cd <workspace>
colcon build --packages-select tram_vehicle_msgs tram_navigation
source install/setup.bash
```

**2. Запуск основной ноды:**
```bash
ros2 launch tram_navigation tram_odom.launch.py
```

**3. Воспроизведение тестового прогона (в отдельном терминале):**
```bash
ros2 bag play <path_to_bag>
```

**4. Проверка выходов и задержки публикации:**
```bash
ros2 topic hz /result/velocity
ros2 topic echo /result/position
```

## 3. Математическая модель

В основе алгоритма лежит физико-математическая модель движения трамвая и фильтр Калмана для обработки зашумленных данных.

### Динамика 2-го порядка
Дифференциальное уравнение продольного движения описывается следующим образом:
$$m \frac{dv}{dt} = F_{\text{тяг}}(u) - F_{\text{сопр}}(v)$$

Где:
* Тяговое усилие: $F_{\text{тяг}} = k_{tr} \cdot u$
* Сила сопротивления (по формуле Дэвиса): $F_{\text{сопр}} = c_0 + c_1 v + c_2 v^2$

### Структура алгоритма
1. **Синхронизация данных:** Используется кастомный буфер `SafeSyncBuffer` с окном допустимой рассинхронизации $\pm 50$ мс.
2. **Фильтрация и детекция слипа (буксования/юза):** Применяется Расширенный фильтр Калмана (EKF). Реализована адаптивная ковариация измерений $R$, которая динамически увеличивается при детектировании проскальзывания колес.
3. **Стояночный режим (ZUPT - Zero Velocity Update):** При выполнении условий остановки скорость принудительно фиксируется в $0$, а координата пройденного пути замораживается для предотвращения дрейфа.

## 4. Параметры и допущения

Конфигурация модели загружается из файла `config/params.yaml` (или `model_params.json`). 

**Основные параметры системы:**
* **Масса ($m$):** $25,000$ – $28,000$ кг
* **Коэффициент тяги ($k_{tr}$):** $1620.5$ Н/нотч
* **Коэффициенты Дэвиса:** 
  * $c_0 = 285.2$ Н
  * $c_1 = 18.4$ Н·с/м
  * $c_2 = 0.76$ Н·с²/м²
* **Окно синхронизации:** $0.05$ с

**Допущения:**
В связи с отсутствием цифровой карты пути ($pathgraph$) в рамках текущего задания, модуль публикует 1-D одометрию вдоль рельсов в формате $(s, 0, 0)$, что полностью соответствует условиям кейса.

## 6. Ограничения решения и план развития

### Текущие ограничения
* **1-D одометрия:** Без интеграции карты невозможно оценивать боковой сдвиг $y$ и ориентацию на кривых участках пути.
* **Отсутствие учета рельефа:** В текущей версии не производится онлайн-оценка угла уклона пути.

### План развития (Future Work)
1. **Интеграция графа путей:** Подключение карты ($pathgraph$) для автоматической проекции одномерной координаты на плоскость: $s \to (x, y, \text{yaw})$.
2. **Расширение пространства состояний:** Включение оценки текущего уклона пути $i(s)$ и коэффициента сцепления (адгезии) $\mu$ в расширенный вектор состояния EKF для повышения устойчивости при сложных погодных условиях.
3. **Оптимизация:** Полный перевод прототипа на строгую C++ реализацию для дальнейшей минимизации задержек до микросекундного уровня и интеграции в real-time контур управления (RTOS).
